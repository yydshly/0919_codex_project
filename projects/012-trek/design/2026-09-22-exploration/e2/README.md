# E2：从真实照片到地理布局中的景观素材

## 这轮实际做了什么

1. 沿用四张有来源的历史实拍，逐张登记可见建筑特征及证据边界。
2. 使用内置 image_gen 生成钟楼、鼓楼、大雁塔和兵马俑素材；每处独立生成，以钟楼候选作为其余素材的风格参考。
3. 大雁塔首版只有六层，并捏造高砖台与栏杆，拒收；再次生成后为七层，去掉了高台。失败首版与实际修正提示词均保留。
4. 保留四份原始 RGBA PNG，不后期改写像素。程序把图片容器中心对准 E1 已计算的四个地理锚点，通过 SVG image 呈现真实素材。
5. 注入错位、互换、漏放和过度放大，检查实际素材绑定、坐标与矩形关系，输出检查记录。

本轮共调用内置图像生成工具 5 次，得到 4 份当前候选与 1 份拒收候选。工具没有公开具体模型版本，本项目以 `null` 保留，不填猜测值。全部素材与照片已在本项目保存，不依赖工具默认输出目录。

## 可观察的结果

- 钟楼的中央宝顶、紧凑楼身与砖台拱洞，和鼓楼的长屋脊、端部山墙及鼓列能够区分。
- 修正后的大雁塔可数出七层。这个实例证明，素材身份正确、位置正确并不能保证建筑形象正确。
- 兵马俑参考为一号坑内部历史照片，只支持“内部军阵主题符号”；当前微缩剖块不是完整景区的真实鸟瞰或坑区精确平面。
- 四张图片都有真正的透明通道，仍存在局部彩色光边、淡残留和生成补绘。当前风格较一致，但边缘精修、细节真实性与整图自然衔接尚未达到成品验收。
- 84 px 方形图片框在当前 E1 分区骨架中没有相交；放大素材会出现框重叠。这与真实建筑主体的可见面积不同。

照片与生成候选的逐项对照见 [视觉审查](VISUAL-REVIEW.md)，参考本身的限制见 [参考证据](REFERENCE-REVIEW.md)。

## 几何与图像，分别验收

程序可验证地点编号、文件哈希、素材引用、画幅、框尺寸、中心对齐和矩形相交。这里没有用模型视觉自动识别建筑内容，也没有计算“真实主体可见率 90%”；`visibleAssessment` 明确为未测量，`releaseReady` 为 false。原设计中的完整 E2 验收仍未达成。

当前选择“图片框中心对应地理中心”作为可复现基准，并非已经找到了建筑接地点。透明留白、拍摄透视与符号化主体会影响视觉中心。下一轮需定义每张素材的内容锚点，并重新评估密集城区的展示尺度。

每个局部图幅使用独立比例。钟鼓楼片区、城南与临潼的页面位置是排版；真实全域关系由定位小图解释，不能按图框的位置推断实际方向。锚点均沿用 E1 的中心点，不能作为已核实入口。

## 实验操作

- 选择四处地点，比较实拍与生成素材；大雁塔同时保留拒收首版。
- 在实际合成图中点选图片，观察同一地点资料同步；切换锚点／占位框辅助显示。
- 调节素材尺寸或放大画布阅读。放大画布只改变观看比例，不改变 E1 地理坐标。
- 选择四种故障，检查失败项；导出当前合成记录时保留当前故障状态。

## 对产品方向的影响

“真实资料 → 生成素材 → 程序放置 → 地点关联”已获得一组实际样本。接下来应优先完善素材外形与透明边缘、定义内容锚点，并检查更多地点的图面密度，然后再推进从图到入口、预约资料和导航的 E3。不能用一张漂亮图片代替地点资料维护，也不能用布局检查替代图像内容检查。
