# 研究笔记

## 2026-09-20 · 能力展台与渲染复现

固定上游提交：`5e71af35a2daee492dd3ea93e5e8903f32dcd13c`。在 Windows / Node 22.15.0 上运行。

### 复现方法

1. 从上游挑选 8 个有代表性的镜头，复制其实际 TSX 与必要共享组件、纹理。
2. 用 Remotion Player 实时运行，以 Thumbnail 从同一组件生成预览帧。
3. 为 BlurSlide 和 CounterConfetti 添加有限的内容参数，保持主要运动曲线。
4. 用 Sequence 将 6 个镜头串联；每段仍按自身帧号与时长计算。
5. 用同一 Reel 组件通过 Remotion CLI 导出 MP4，并抽帧检查。

### 来源与设计判断

上游的核心积累在于镜头的语义、节奏和调校参数。示例素材不等于真实产品适配完成；真正投入制作还需要重做素材、品牌与叙事。

本页没有启动 AI 推理服务或在线导出后端。AI 响应镜头是纯动画，界面中的检查结果是上游演示文案。参数修改不持久化，串片下载为预先渲染的默认版本。

## 2026-09-20 · 对比结论与收录定位

将项目摘要与网页统一为「基于 Remotion 实现的动效素材合集」。上游附有制作指引、模板与交付工具，但本次验证主要覆盖效果层。

对照此前 [TalkCraft 研究](https://yydshly.github.io/0914_codex_project/003-video-talkcraft/) 和 [Vibe Motion 研究](https://yydshly.github.io/0914_codex_project/004-vibe-motion/)，文字、卡片、数字、转场与逐帧渲染明显重叠；侧重点分别是产品宣传、口播同步和更广泛的 2D / 3D 工程。完整对比见 [研究结论](../README.md#研究结论与范围)。

对我们按「补充素材库，新增能力有限，独立研究优先级较低」收录。保留镜头源码、页面切片与运镜方法、调参及失败经验；后续以自己的产品短片与实际制作耗时验证价值，不把示例运行视为效率或质量优势的证据。
