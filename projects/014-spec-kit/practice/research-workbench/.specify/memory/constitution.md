# 研库 · 开源项目研究工作台 Constitution

## Core Principles

### I. 真实交付
必须交付可实际操作的产品。初始化、规格、计划、任务、验收来自本次执行；不得用预设动画冒充 AI 开发。

### II. 使用已有事实
初始目录必须来源于现有研究项目元数据，标明研究快照与来源。用户定制选择与代理默认假设必须分别记录。

### III. 保存可信
用户定制、结论和待办必须持久保存；操作失败不得显示成功，不得清空输入。用户数据与测试数据必须隔离。

### IV. 先约定再验证
需求必须明确验收场景；核心流程必须实际运行浏览器和服务端测试。不得仅以任务勾选作为完成证据。

### V. 可用与克制
界面使用中文，支持键盘与手机宽度，错误可理解。只开发规格中的功能，所有新增范围必须先更新规格。

## Scope Constraints
个人本地工具；默认只监听回环地址，不提供多人登录、云同步或自动联网更新。不得向外部服务提交研究或用户数据。

## Development Workflow
按 specify → plan → tasks → implement → converge 执行。每阶段留下真实产物；人工或 AI 结论必须与原始执行报告区分。

## Governance
改动原则时记录原因并递增版本；开发与最终核对必须复查这五项原则。无例外时采用最小可用架构。
