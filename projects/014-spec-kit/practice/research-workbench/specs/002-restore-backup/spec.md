# Feature Specification: 从备份恢复研究记录

**Created**: 2026-09-22
**Status**: Ready for planning
**Input**: 用户要求“继续用一个产品真实演示他的能力”。代理选择给现有研库增加备份恢复，用一次真实功能迭代展示Spec Kit。此选择已在会话说明；具体规则为本次设计，不是用户逐项原话。

## User Scenarios & Testing

### US1 - 先看清将恢复什么 (P1)
用户选择研库导出的备份文件，看到空间名称、结论数、任务数与替换范围，决定是否继续。
**Independent Test**: 预览有效文件后检查当前空间完全未变；取消无任何写入。
**Acceptance Scenarios**:
1. Given 有效备份，When 预览，Then 显示备份与当前名称、结论数、任务数，说明替换个人记录但保留研究目录事实。
2. Given 文件损坏、字段超限、重复任务、未知项目或超过5MiB，When 预览，Then 明确拒绝，不改当前记录。

### US2 - 确认恢复并防止覆盖新编辑 (P1)
用户明确确认后，一次恢复备份中的空间配置、个人结论、跟进状态与全部任务。预览之后若出现新编辑，必须重新预览。
**Independent Test**: 导出A→修改成B→预览并恢复A→重启，核对个人字段恢复、原研究事实不变。
**Acceptance Scenarios**:
1. Given 有效且仍新鲜的预览，When 明确确认恢复，Then 个人字段全部恢复，已不在备份的任务被移除。
2. Given 预览后其他页面改动数据，When 确认恢复，Then 拒绝并提示重新预览，不覆盖新数据。
3. Given 恢复过程失败，When 读取现有空间，Then 没有半恢复的混合结果。

### US3 - 能撤销最近一次恢复 (P2)
恢复成功后用户可以撤销本次恢复；若之后已有任何新编辑，则拒绝撤销以保护新数据。
**Independent Test**: B→恢复A→撤销回B；恢复A→新增任务→撤销被拒绝。
**Acceptance Scenarios**:
1. Given 恢复后无新编辑，When 撤销，Then 回到恢复前的个人数据。
2. Given 恢复后有新编辑或已撤销，When 再撤销，Then 拒绝，不覆盖新数据。

### US4 - 看懂Spec Kit实际参与的开发过程 (P2)
演示页展示本轮每一步的实际产物和规则到实现的对应，另提供独立演示空间供真实操作。
**Independent Test**: 查看本轮spec、plan、tasks和验收；在演示空间操作，不改个人空间。
**Acceptance Scenarios**:
1. Given 开发演示，When 查看阶段，Then 清楚区分Spec Kit规程、AI产品设计和真实执行结果。
2. Given 独立演示空间，When 恢复示例备份或撤销，Then 只改变明确标记的演示数据。

### Edge Cases
- 备份只接受本工具schemaVersion=1，项目ID集合必须与当前目录一致，任务最多1000项。
- 备份中的项目名称、摘要、标签和源链接不覆盖当前可信研究目录；只恢复个人note/status。
- 恢复后旧页面的版本不可重新生效，防止旧编辑在恢复后误保存。
- 预览后换文件必须重新预览；失败或取消不悄悄写入。
- 输入文字显示为纯文本；所有实验数据和个人空间物理隔离。

## Requirements
- **FR-001**: 提供选择JSON备份与预览；名称、目标、标签、状态、结论、任务标题与日期沿用原产品限制，不静默截断。
- **FR-002**: 限制5MiB、schemaVersion=1、16个既有项目恰好一次、唯一任务ID、最多1000任务；未知项目或不完整备份拒绝。
- **FR-003**: 预览是只读操作，展示当前与备份摘要及全量替换范围；未确认不得恢复。
- **FR-004**: 确认恢复必须一次完成空间设置、全部个人项目字段和任务替换；失败全部回滚。
- **FR-005**: 保留原始目录元数据；恢复不添加或删除目录项目。
- **FR-006**: 预览后任何记录变化均使该预览失效；提示重新预览，不覆盖新改动。
- **FR-007**: 最近一次恢复可撤销；撤销前必须确认恢复后没有新编辑；撤销必须原子完成且仅可执行一次。
- **FR-008**: 恢复和撤销之后旧页面版本一律失效；服务重启后已提交数据及可用撤销记录保留。
- **FR-009**: 页面中文、支持390/1440px、键盘操作、明确成功或失败；演示空间和个人空间分开。
- **FR-010**: 本次必须先执行失败基线，再验证导出→修改→恢复→撤销、冲突、无效输入、事务失败及旧页面失效；保存实际报告。
- **FR-011**: 开发演示逐步展示本轮实际规格、方案、任务、实现及验证，并准确区分谁提供规程、谁写业务代码。

## Key Entities
- 备份：空间配置、个人项目字段、任务集合、来源版本。
- 恢复预览：文件内容及当前空间版本依据、替换摘要。
- 撤销记录：恢复前快照、恢复后版本依据、唯一恢复标识。

## Success Criteria
- **SC-001**: 完成一次导出→修改→预览→恢复→撤销，个人数据分别与对应快照一致。
- **SC-002**: 无效备份、过期预览、旧页面保存和不允许的撤销均被拒绝且数据不变。
- **SC-003**: 实际服务端与浏览器报告可复查；独立演示空间提供可操作成品。

## Assumptions
仍是本机单用户工具，无云同步和备份迁移协议；恢复同一研究目录的个人数据。恢复确认是产品必要交互，不需要用户在本次开发会话批准编写代码。
首版原规格不包含导入；本002功能是用户要求继续实战后的新迭代，原001记录保持历史含义。
