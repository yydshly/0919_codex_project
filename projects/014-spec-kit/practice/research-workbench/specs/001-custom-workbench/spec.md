# Feature Specification: 研库 · 定制开源项目研究工作台

**Feature Branch**: 未创建独立分支，功能目录独立定位
**Created**: 2026-09-22
**Status**: Ready for planning
**Input**: 用户要求“一个真实的场景，从定制到最后的产品呈现，进行真实的演示，用这个库的能力”。代理提出三个场景；尚未收到选择时，以现有开源库研究作为默认场景，不宣称用户已确认。

## User Scenarios & Testing

### User Story 1 - 定制我的研究空间 (Priority: P1)
用户首次进入，设置空间名称、研究目标、关注方向和默认展示方式，进入包含真实研究项目的个人空间。
**Why this priority**: 让定制真实改变可使用的产品，而非只生成说明。
**Independent Test**: 填写配置，完成定制，刷新或重启服务后仍显示同样的配置和项目。
**Acceptance Scenarios**:
1. Given 新空间，When 填写名称、目标、关注标签并选择默认展示，Then 产品名称、目标、关注视图和默认页面反映选择。
2. Given 已定制空间，When 修改设置并重新打开，Then 新设置保留且研究记录不丢失。
3. Given 名称为空或超长，When 保存，Then 明确拒绝，保留输入，不静默截断。

### User Story 2 - 查找与比较真实项目 (Priority: P1)
用户浏览已有研究目录，搜索、组合筛选、选择最多三个项目，并在比较页查看能力摘要、标签、研究状态和自己的结论。
**Why this priority**: 直接服务当前的开源项目研究工作。
**Independent Test**: 搜索 Spec Kit，查看来源；选择两项比较，项目与字段保持一致。
**Acceptance Scenarios**:
1. Given 现有研究快照，When 搜索名称、摘要或标签并筛选跟进状态，Then 仅显示匹配项，空结果可清除筛选。
2. Given 已选择三个项目，When 尝试选择第四个，Then 显示上限提示且原选择不丢失。
3. Given 项目详情，When 打开来源，Then 指向其真实源库；研究摘要明确为快照，不声称实时联网更新。

### User Story 3 - 形成结论并安排下一步 (Priority: P2)
用户填写自己的应用判断、修改研究进度，并添加带可选截止日期的下一步任务。任务可完成、重新打开或删除。
**Why this priority**: 将看过的资料转为可持续跟进的个人工作。
**Independent Test**: 保存一个结论和任务，刷新后保留；完成任务后看板和计数同步变化。
**Acceptance Scenarios**:
1. Given 一个项目，When 保存结论并切换待研究/研究中/已形成结论，Then 卡片、筛选和详情一致。
2. Given 项目任务，When 完成或重开，Then 看板与未完成计数同步，刷新后状态不变。
3. Given 任务，When 删除并确认，Then 仅删除该任务；取消时保持原样。

### User Story 4 - 带走成果并核对制作过程 (Priority: P2)
用户导出完整空间备份或可读研究报告，并查看真实定制需求、方案、任务、源代码和验收记录。
**Why this priority**: 可用成果与 Spec Kit 方法都应可以复查。
**Independent Test**: 应用筛选后导出，仍包含全量项目和个人记录；制作过程文件与本地原文一致。
**Acceptance Scenarios**:
1. Given 已保存个人配置和结论，When 导出，Then 完整备份与报告包含相应信息，不受当前筛选影响。
2. Given 制作过程页面，When 打开产物或验收记录，Then 可看到实际文件与执行结果，未执行时不得显示通过。

### Edge Cases
- 保存失败保留表单；重开对话框前明确未保存状态，关闭前有丢弃确认。
- 空搜索、无关注方向、未定制、无待办均提供可理解的空状态。
- 超长文本和非法状态被拒绝；用户文字只作为文字显示。
- 两个页面编辑同一项目：旧版本保存被拒绝，不静默覆盖新结果。
- 未知接口、错误请求、非法日期、数据库故障提供明确失败，不伪装成功。

## Requirements
### Functional Requirements
- **FR-001**: 设置包含空间名称1..40字符、目标0..200字符、关注标签0..8个、默认视图全部/关注；必须可再次修改。
- **FR-002**: 初始项目必须取自当前16个研究项目的元数据快照，展示名称、摘要、标签、源库、原研究状态、快照时间；不得伪造评分。
- **FR-003**: 支持不区分大小写的名称/摘要/标签搜索，与跟进状态及关注视图组合筛选；清空筛选能恢复全部。
- **FR-004**: 支持2..3个项目横向比较，限制第四个选择；少于两项给出指引。
- **FR-005**: 每个项目可保存个人结论0..2000字符及待研究/研究中/已形成结论状态，刷新后保留。
- **FR-006**: 每个项目可新增任务，任务标题1..120字符，可选真实日期，支持完成/重开、确认删除。
- **FR-007**: 设置、结论、任务须在服务重启后保留；仅成功保存后更新界面；失败保留输入。
- **FR-008**: 旧版本修改同一条设置/项目/任务必须提示冲突，保留输入并允许重新读取。
- **FR-009**: 导出完整空间JSON备份和可读Markdown报告，不受搜索或筛选影响；下载前清楚说明备份范围。
- **FR-010**: 首次定制与产品主界面均支持键盘和390px、1440px屏幕；比较表允许局部横向滚动。
- **FR-011**: 提供独立制作过程页，展示实际输入、阶段产物、源文件下载及真实验收报告；内容有明确来源。
- **FR-012**: 个人工具仅在本机使用，数据不发往第三方；本次数据文件、测试数据、研究快照分开。
- **FR-013**: 必须编写并真实执行核心保存、筛选、比较、任务、导出、异常和持久化验收；报告失败须如实记录。

### Key Entities
- 空间配置：名称、目标、关注方向、默认视图、版本。
- 研究项目：原始研究事实与来源；个人结论、进度和版本与其关联。
- 跟进任务：所属项目、标题、截止日期、完成状态、版本。
- 开发证据：实际阶段文件、命令日志和验收报告。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 用户可一次完成名称、目标、关注方向和默认视图定制，刷新后四项一致。
- **SC-002**: 16个项目全部可检索，选中的2..3项可对照；个人结论与任务可持久保存。
- **SC-003**: 所有规定验收场景实际运行，输出逐项通过/失败记录，失败修复后重新验证。
- **SC-004**: 两个目标屏幕宽度均无整页横向溢出，主要操作可由键盘触达。

## Assumptions
- 场景由代理依据现有工作默认选择；用户后续选择优先。
- 单用户本地使用，无登录、云同步、多人协作、自动爬取和在线模型调用。
- 定制页面配置已实现产品，不假装点击按钮即可即时生成任意新软件；Spec Kit 在本次开发会话中使用。
- 用户可管理已有目录的研究结论与待办；首版不新增/删除目录项目，不提供备份导入。
