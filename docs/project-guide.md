# 项目收录与编号规范

## 编号与目录

- 子项目位于 `projects/NNN-slug/`，例如 `001-example-project`。
- 编号使用三位数字，从 `001` 起按收录顺序递增；首页按编号升序展示。
- 编号是固定标识，不因研究优先级变化而调整。停止研究时改为“已归档”，保留目录和编号，避免旧链接失效或编号被复用。
- `slug` 只使用小写英文字母、数字与单个连字符；创建后尽量不更名。
- 模板放在 `templates/` 中，不占用正式项目编号。

## 单一信息来源

每个子项目的 `project.json` 是首页索引与图览的数据来源。修改后运行 `python scripts/project.py sync`，不要手工修改根 README 中带自动生成标记的区域。

| 字段 | 用途 |
| --- | --- |
| `id` | 固定编号，如 `001` |
| `slug` | 目录名称中的英文短名 |
| `name` | 展示名称 |
| `summary` | 一句话用途与研究重点 |
| `source` | 上游仓库 HTTPS 链接 |
| `status` | 待研究 / 研究中 / 已复现 / 已完成 / 已归档 |
| `tags` | 技术或主题标签数组，可留空 |
| `demo` | 已可访问的演示 HTTPS 链接；未部署时留空 |
| `cover` | 相对子项目目录的图片路径；没有图片时留空 |

新增命令会同时创建元信息、README、笔记和图片目录。`check` 会校验目录与编号一致性、必填信息、封面文件是否存在，以及首页是否已同步。提交和拉取请求也会自动执行此检查。

## 每个项目记录什么

1. 项目解决的问题、收录原因和上游地址。
2. 研究时的上游版本或提交、许可证和技术栈。
3. 实际环境、运行命令、配置方法和复现结果。
4. 架构理解、关键实现与自己的实验。
5. 截图说明、演示地址、当前结论与后续计划。

先链接上游仓库；需要本地阅读时可放在被忽略的 `.local/` 下。需要保存改动时，在对应子项目中建立 `src/`、`examples/` 或 `patches/`，并明确来源与修改范围。不要直接把带 `.git` 的嵌套克隆目录当作普通文件提交。

## 图片与资源

封面建议命名为 `assets/cover.png` 或 `assets/cover.webp`。其他截图按内容命名，在子项目 README 中使用相对路径，并写清楚展示的功能或结果。首页只展示一张封面，避免随项目增多变得过长。

截图应来自实际研究或演示，未添加封面时不会显示空图片。大视频、模型权重和数据集通过外部链接引用。

## 日常维护

```sh
python scripts/project.py sync
python scripts/project.py check
```

根 README 保持摘要与导航用途。实验日志写在子项目 `notes/`，详细安装说明与研究结论写在子项目 README。
