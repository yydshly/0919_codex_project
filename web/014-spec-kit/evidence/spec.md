# Feature Specification: 开源项目收藏夹

**Feature Branch**: 未创建分支；独立演示目录 `001-resource-shelf`

**Created**: 2026-09-22

**Status**: Ready for planning

**Input**: 用户要求“用一个真实场景实际演示这个库的能力”。选择当前开源项目研究工作中的收藏、查找与备份场景；具体范围见 `../../../../notes/live-run/input.md`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 收藏项目，下次继续研究 (Priority: P1)

用户输入项目名称、GitHub 仓库首页、标签和备注，保存后可以刷新页面继续查看。

**Why this priority**: 这是保存研究线索的最小可用功能。

**Independent Test**: 添加一个不在列表中的项目，刷新，核对内容完全保留。

**Acceptance Scenarios**:

1. **Given** 首次打开，**When** 查看列表，**Then** 显示三条明确标为初始示例的仓库，并说明收藏只在本浏览器保存。
2. **Given** 有效名称与仓库首页，**When** 添加，**Then** 新记录显示，状态为待研究，刷新后仍存在。
3. **Given** 已收藏一个仓库，**When** 使用大小写、尾斜杠或 `.git` 变体再次提交，**Then** 提示重复，不增加或覆盖记录。
4. **Given** 空名称或无效仓库链接，**When** 提交，**Then** 显示具体问题，保留输入。

### User Story 2 - 找到项目并更新研究进度 (Priority: P2)

用户通过名称、标签、备注搜索，再按待研究或已研究筛选，可以切换状态。

**Why this priority**: 收藏后需要快速找到下一项研究对象。

**Independent Test**: 搜索备注中的独有词，再切换该条状态与过滤条件，刷新后状态保持。

**Acceptance Scenarios**:

1. **Given** 多条项目，**When** 搜索名称、备注或标签，不区分英文字母大小写，**Then** 展示匹配项目。
2. **Given** 搜索结果，**When** 选择状态，**Then** 两种条件同时生效。
3. **Given** 一条待研究项目，**When** 标为已研究，**Then** 状态和数量同步变化，刷新后保留。
4. **Given** 当前条件无结果，**When** 查看列表，**Then** 显示无匹配提示及清除筛选操作。

### User Story 3 - 导出与整理收藏 (Priority: P3)

用户导出全部收藏为 JSON 文件，删除不需要的项目后可撤销最近一次删除。

**Why this priority**: 本机保存需要用户可带走的备份；整理操作应可恢复。

**Independent Test**: 搜索只保留一条时导出，核对导出仍包含全部记录；删除 A、添加 B、撤销删除后 A 和 B 均存在。

**Acceptance Scenarios**:

1. **Given** 存在筛选条件，**When** 导出全部，**Then** 文件包含所有收藏及其完整字段。
2. **Given** 删除一条记录，**When** 本页面刷新前撤销最近一次删除，**Then** 恢复该条而不覆盖期间其他修改。
3. **Given** 所有记录已被删除，**When** 刷新，**Then** 保持空收藏，不恢复初始示例。

### Edge Cases

- 保存被浏览器阻止或空间不足：明确显示未保存，保留原数据和输入。
- 已有存储损坏或版本不支持：展示恢复说明，保留原始内容，禁用写操作；允许导出原始存储供恢复。
- 仓库链接含查询参数或片段：忽略这些部分；拒绝其他网站、非仓库首页路径和带登录信息的链接。
- 超长名称、备注、标签：按明确长度限制提示，不截断后偷偷保存。
- 其他标签页更新：同步已保存数据，不清空尚未提交的表单；不保证同时写入的事务性。
- 用户文本包含 HTML：作为普通文字显示，不作为网页执行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 提供中文的名称、链接、标签、备注输入与新增操作。名称必填且最多80字；链接必填；备注最多300字；最多6个标签、每个最多20字。
- **FR-002**: 校验 GitHub 仓库首页格式并归一化去重；不声称联网验证仓库存在。
- **FR-003**: 成功保存的收藏和状态在同一浏览器同一站点刷新后保留；页面明确显示存储范围。
- **FR-004**: 搜索名称、标签与备注；支持全部、待研究、已研究状态过滤，两种条件组合生效。
- **FR-005**: 支持双向切换研究状态，实时显示总数、待研究数与已研究数。
- **FR-006**: 导出完整收藏及所有字段为 JSON 文件，不受当前筛选影响。
- **FR-007**: 删除可撤销最近一次操作；撤销不覆盖删除后新增的记录；刷新后撤销记录不保留。
- **FR-008**: 区分首次使用、空收藏、无搜索结果和存储错误；存储错误不冒充保存成功。
- **FR-009**: 标记初始示例，允许全部删除；全部删除后保持空集合。
- **FR-010**: 所有操作可用键盘执行；在320px手机和桌面上不出现页面横向溢出。
- **FR-011**: 实际运行浏览器测试并保存结果；说明页可查看本次实际需求、方案、任务与验证记录。
- **FR-012**: 其他标签页修改后刷新列表；保留未提交输入，不承诺同一时刻并发写入强一致性。

### Key Entities *(include if feature involves data)*

- **收藏项目**：唯一标识、名称、规范化仓库链接、标签、备注、研究状态、创建与更新时间、是否来自初始示例。
- **收藏集合**：结构版本、保存时间、全部项目。
- **最近删除记录**：项目内容与原位置，刷新前可撤销。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新增、状态修改及刷新复查的验收步骤100%通过。
- **SC-002**: 筛选后导出的数量与全部收藏数量一致，每条记录字段完整。
- **SC-003**: 重复、非法链接、读写失败、删除撤销的测试通过，且失败操作不会抹去既有内容。
- **SC-004**: 320px、390px、768px和1440px宽度下无页面横向溢出，核心功能可操作。
- **SC-005**: 用户能从真实成品进入此次使用的需求、方案、任务及实际测试结果，而不只看到预制的示例摘要。

## Assumptions

- 本次为单人本机工具，使用常见现代浏览器；不提供账号、云同步、批量采集、自动读 GitHub 信息或 JSON 导入。
- 用户自行填写信息，填写 GitHub 链接不代表访问或连接该仓库。
- 只支持仓库主页；初始示例为 Spec Kit、VideoCaptioner 和 Blinko。
- 用独立浏览器测试环境验证，不修改用户已经保存的收藏。
- 在网页中展示开发证据是此次真实演示的一部分；用户收藏数据不加入这些证据。
