RESEARCH NOTE 005 / VIDEO LOCALIZATION

获取视频，
处理与转换，
发布到 A 站或 B 站。

获取 YouTube 视频，经过字幕识别、翻译、烧录或转码等处理后，发布到 A 站（AcFun）或 B 站（bilibili）；支持单平台或双平台发布。 视频主体来自原内容，主要处理语言、字幕、编码与发布信息。

01 / 接入

找到视频，形成任务

手动输入 YouTube 链接，或监控频道和关键词；下载由 yt-dlp 处理。

依赖网络与账号状态；CookieCloud 可选。
02 / 本地化

处理语言与字幕

复用已有字幕，或调用 Whisper / Voxtral API 识别；按配置翻译、整理、质检与烧录。

语音识别 API 与本机 GPU 转码是不同能力。
03 / 文案

准备目标平台信息

翻译标题和简介，生成或应用标签，推荐分区；为视频提供适合发布的说明。

输出质量依赖模型、提示词与人工复核。
04 / 审核

让任务可以停下来

可选文本检测，处理标题、简介、标签；不通过时进入人工审核。

本次代码路径不能证明整段视频已经过审核。
05 / 发布

送到 AcFun / bilibili

支持单平台或双平台。启用自动模式才自动上传，否则保留准备上传状态。

需要目标平台登录状态和正确上传参数。
06 / 运维

追踪长期运行

Web 管理、任务日志、监控、清理与事件通知，让处理结果可查。

通知支持企业微信、Server酱、message-pusher。

03 / UNDER THE HOOD

值得借鉴的是任务如何被组织。

01

阶段检查点

任务记录完成的阶段，重跑时可跳过已完成工作；后台通过并发额度控制处理数量。

02

字幕质量门控

质量状态参与烧录前的判断。识别失败、质检不通过和质检不可用分别记录原因。

03

部分成功恢复

分别保存各平台上传结果，双平台部分成功后可只重试未成功的平台。

04

通知独立投递

消息先保存在 SQLite，再由后台投递、失败重试；达到重试上限后标记失败。

以上为源码中可见的机制；实际稳定性、并发容量和恢复效果仍需要运行验证。

04 / WHY IT MATTERS

对我们，有三种明确的价值。

01

自有内容的跨语言分发

将自己的 YouTube 视频转为中文版本，减少字幕、发布文案与平台上传之间的重复操作。

02

获授权内容的本地化

为课程、访谈等建立处理流程，把人工注意力集中到术语、时间轴和最终发布内容上。

03

内容工具的工程参考

借鉴阶段检查点、人工介入、部分成功恢复与通知重试，设计我们自己的内容处理系统。

05 / BEFORE USING IT

理解边界，再考虑实际使用。

需要准备什么？

可通过 Docker 或本地方式运行。需要视频来源与目标平台的账号状态、网络、存储和 FFmpeg；使用 ASR、翻译或审核时配置相应服务。GPU 不是所有运行方式的统一前提。

它能生成新视频、配音，或发到所有平台吗？

本次阅读确认的是已有视频处理与 AcFun / bilibili 发布。没有确认文生视频、复杂剪辑、配音生成，或抖音、快手、小红书发布能力。

自动审核能替代人工确认吗？

文本审核和字幕质检检查不同对象，均不能等同于完整视频审核或逐句校对。当前主流程检查标题、简介和标签，封面检测在该路径中被跳过。内容检测也不会授予转载权限，应使用自有或已获授权素材。

这次已经验证到哪一步？

已经核对上游说明与关键源码，重新构建研究展示页。没有部署上游服务或连接真实账号；字幕准确性、API 成本、处理速度及平台上传成功率仍待实测。
