# 研究与验证记录

日期：2026-09-22。

## 依据

本次查阅了上游 README、官方功能文档、DocType 与 REST API 文档，以及 hooks.py、Leave Application、Salary Slip、Payroll Entry 和前端依赖配置。记录的 develop HEAD 为 `6060fbdb122041aa6af41723a6533fe28f460f6c`。develop 为开发分支，本页不指定生产部署版本。

源码要点：

1. `required_apps` 声明 ERPNext 依赖。
2. 请假控制器在 validate、on_submit、on_cancel 中处理校验、考勤和假期台账。
3. 工资单支持条件与公式；批量核薪可创建相关会计凭证。
4. 调度配置包含自动考勤、面试提醒等；API 按调用者权限执行。

## 验证范围

初期验证对象为本项目原创的前端教学模型。随后已独立部署官方 HRMS 16.19.0（version-16），通过真实数据库与官方控制器生成虚拟员工、请假、考勤和工资单，并验证浏览器中的计薪 21 / 22 天及净工资 11,454.55 元；未进行生产性能、所有角色权限或中国薪税配置的验证。

教学模型的 8 项业务测试全部通过，覆盖年假余额、无薪假扣款、拒绝、撤销、过期工资快照、无效申请、月度累计限制和本地状态恢复。

新增研究页将当前 v16 源码理解整理为 6 组、24 维，提供完整能力图、角色说明切换、时间规则示例和源码链接。已检查专题展开、角色切换、390px 窄屏布局及 SVG 总览图。

浏览器已实际验证：批准林知夏年假后余额变为 6 天；批准周予安无薪假后试算为 11,454.55 元；撤销后出现过期提示，重新计算恢复 12,000 元。员工搜索、申请提交、事由中的尖括号作为文字显示、刷新恢复、能力详情及架构切换均完成检查。

390 像素宽度下，总览未产生页面横向溢出；工资表在自身容器内横向滚动，不撑开页面。封面来自本项目真实浏览器渲染。

集成时工作区还有其他子项目正在创建，标准全局索引同步曾被缺失的其他项目元信息阻塞。本项目使用共享 `scripts/project.py` 的索引渲染器生成 011 的行和图览，再定向合入总索引，保留其他任务的现有条目；没有修改其他子项目内容。

## 数据处理

模拟状态只写入当前浏览器 localStorage。不发送到服务端。页面对用户填写事由和搜索内容做 HTML 转义；应用不使用第三方前端依赖、字体或远程图片。关闭对话框支持 Escape，主要交互提供可见焦点、表单标签与状态播报。

## 未覆盖

实际账号与权限隔离、假期日期冲突、班次与打卡、地区薪税、ERPNext 记账、银行付款、消息推送、招聘及绩效实际业务。相应模块明确区分为官方能力说明。
