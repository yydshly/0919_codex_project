01 / CAPABILITIES

它能做什么

输入是文稿、可选的声音描述或参考录音；输出是一段合成语音。

01

文字配音

把文章、讲稿和产品说明读出来；官方支持 30 种语言及 9 种中文方言。

02

声音设计

用文字描述音色、年龄感、情绪或语速，生成新的声音，无需录音。

03

音色克隆

参考录音提供目标音色，可配合风格指令改变表达；此模式不要求录音逐字稿。

04

延续式克隆

同时提供录音与准确逐字稿，让新语音更紧密地延续录音中的节奏和表达。

05

流式音频输出

逐块返回已生成的声音，适合在应用里边收边播放；也可批量生成音频。

06

定制声音

支持 LoRA 与全量微调，可针对特定说话人、风格或领域进一步适配。

在语音助手里，它负责把回答“说出来”。语音识别、对话理解和翻译，需要其他组件配合。

02 / HOW IT WORKS

底层怎样生成声音

先规划说什么、怎么说，再逐块合成声音细节。

输入

文字 + 可选录音

文稿决定内容；声音描述或参考录音提供风格与音色。

压缩

AudioVAE · LocEnc

把参考声音编码为连续特征，再将相邻帧组成较短的序列。

规划

TSLM · FSQ

语言模型提取语义与韵律，形成相对稳定的表达骨架。

细化

RALM · LocDiT

补充音色和声学细节，通过条件流匹配生成下一块特征。

输出

AudioVAE 解码

重复生成后还原为可播放的音频，最高输出 48 kHz。

“Tokenizer-Free”是什么意思？

它主要在连续声音特征空间中生成，不依赖外部离散语音 tokenizer。文字仍会分词，模型内部也有 FSQ 量化结构。自回归负责“一块接一块”，局部流匹配负责每一块的细节。

03 / REQUIREMENTS

运行前需要什么

部署现成权重与训练自己的模型，是两种投入规模。

软件

推荐 Python 3.10–3.12、PyTorch ≥ 2.5，以及 torchaudio 等安装包依赖。

模型文件

需要下载 VoxCPM2 权重，并预留数 GB 磁盘空间。

运行设备

NVIDIA GPU 用 CUDA ≥ 12.0 加速；也支持 Apple MPS 或 CPU 推理，速度随设备变化。

显存参考

官方列出的 VoxCPM2 推理显存约 8 GB。具体占用取决于配置，应预留余量。

微调

需要录音与匹配文字。官方指定配置下，LoRA 约 20 GB、全量微调约 40 GB 显存。

最短安装入口pip install voxcpm

首次运行还需获取模型权重。我们尚未在本机下载和实测模型。

04 / OUR TAKE

对我们有什么意义

把它作为可自部署的语音输出备选组件。现阶段先保留研究结论；出现真实配音需求时，再用自己的文稿和参考录音验证效果。

值得尝试的触发点

需要固定个人或品牌音色、大量更新旁白、多语言配音，或让 AI 助手以指定声音回答。

现在

不必为了收藏模型而单独建设产品或投入训练。

需要时

先做小样，比较读音、音色一致性、自然度、生成延迟和维护成本。

研究层面

连续声音特征、语义与声学分层、自回归加局部流匹配值得学习。

BOUNDARIES

使用边界

  • 长文稿建议分段生成并试听校对，避免语速漂移或杂音。
  • 参考录音宜清晰，官方给出的实用范围为 5–30 秒。
  • 流式音频输出不等于文字逐 token 到达时同步生成语音。
  • 本页是文档与代码研究；没有实测声音质量、显存或速度。
