内容做好以后，
让发布和运营接上。

BrightBean Studio 是可以自行部署的多平台运营后台。
准备好文案、图片或视频，在一个地方完成排期、发布和效果回收。

支持目标Facebook、Instagram、Threads、LinkedIn、TikTok、YouTube、Pinterest、Bluesky、Mastodon、DEV.to、Google 商家资料。

如何接入多数使用开发者应用凭证 + 账号授权；Bluesky 用应用密码，DEV.to 用个人 API key，Mastodon 自动注册 OAuth 应用后授权。

11 个平台 / 13 种连接 · 评论、私信和统计按平台及权限开放 · 目前没有国内主流平台接入

03 / UNDER THE HOOD

界面、后台与平台接口，分工完成。

入口层浏览器界面 / REST / MCP

人、脚本或 AI 提出操作请求

↓
业务层Django + 数据库

保存内容，检查账号范围、权限与审核规则

↓
执行层后台任务 + 平台适配模块

扫描到期内容，转换为各平台官方 API 请求

↓
外部平台发布 · 处理 · 返回结果

收回发布状态、互动与指标

调度

浏览器关了，后台仍可工作。

发布任务注册为每 15 秒扫描一次，结果确认每 60 秒检查一次。服务器和任务进程需要持续运行；周期不等于实际上线延迟承诺。

适配

统一操作，各平台各自实现。

每个平台模块负责授权、发布和取数。新增平台需要真实接口和权限，不能只加一个名称。

展开技术栈与数据模型 +

界面：Django 模板、HTMX、Alpine.js、Tailwind CSS。后端：Django。任务：django-background-tasks。生产数据库：PostgreSQL。媒体：本地持久化存储或 S3 兼容存储。

Post 保存共同内容；PlatformPost 记录每个目标账号的独立状态。后台通过数据库事务认领任务，再调用平台接口。

AI + OPERATIONS

AI 负责理解，
Studio 负责执行。

可通过接口创建草稿、排期、查询素材、读取统计和处理回复。

“把这支视频准备成三个平台的草稿，供我检查；发布后再汇总表现。”可以围绕现有接口搭建的工作流 · 本次未接入

接口仍需检查权限和账号范围。要求审核的工作区会阻止直接排期。自然语言理解和内容生成由外部模型承担。
