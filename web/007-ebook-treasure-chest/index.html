EBOOK TREASURE CHEST / 研究结论

一个个人维护的
电子书链接目录

它把外部网站上的书名、作者、标签和下载地址整理起来，提供分类浏览与关键词搜索。书籍文件由第三方网盘提供，仓库保存的是目录和链接。

我们怎么看

对我们的直接价值较低。现成书目与我们关注的专业技术资料不够贴合；可以保留它“采集目录 → 生成搜索数据 → 发布静态页面”的做法作为小型资料索引参考。

保存了什么如何设计对我们有什么意义核对依据
01 / CONTENTS

它保存了什么？

上游统计记录 1,000 个分类文件、24,071 条书目记录；一本书可能归入多个分类，因此这不是去重后的书籍总数。仓库文件树中未发现 EPUB、MOBI、AZW3 或 PDF 正文文件。

仓库里的目录书名、作者、分类标签、外部下载链接，以及供网页搜索的 JSON 数据。
仓库里的程序采集网页、按标签生成表格、合并数据、更新搜索页的脚本。
书籍文件链接指向第三方网盘，文件是否仍在、格式与质量需要实际核对。

收录方式主要依靠脚本采集；“个人维护”不表示维护者亲自读过或推荐每本书。格式字段由脚本默认填入，不代表逐本验证。

02 / DESIGN

目录是如何做出来的？

  1. 01
    采集外部网站

    Python 按书籍 ID 请求详情页和下载页，提取书名、作者、标签及网盘地址。

  2. 02
    按标签存放

    把一条书目写入一个或多个 Markdown 分类表格。

  3. 03
    生成搜索数据

    合并分类表格为 JSON，交给 GitHub Pages 上的静态网页。

  4. 04
    在浏览器中搜索

    网页一次加载目录，按书名、作者或分类匹配关键词；它不会在搜索时重新查遍互联网。

自动更新主要追踪新增书籍 ID。源码静态核对发现，增量写入可能覆盖同标签旧记录，失败请求也可能被记作已处理；本次未运行上游采集程序。

03 / VALUE

对我们的意义

作为找书工具，它适合搜索已收录的文学、历史、科普、经管等书目。它不能保证找到某一本书；此前核对公开目录时，没有找到《架构师的自我修养》。

作为技术案例，值得借鉴的是轻量目录结构：用文件保存分类，生成统一索引，再用静态网页检索。如果我们建设自己的专业资料目录，需要围绕实际资料来源补上去重、链接检查与备份。现阶段无需围绕这个库投入部署和扩建。

04 / EVIDENCE

依据与范围

结论基于上游提交 93cf3ff 的统计文件、采集脚本、数据转换代码、搜索脚本和工作流。我们没有下载书籍，也没有逐条检查下载地址。完整核对结果见项目文档。
