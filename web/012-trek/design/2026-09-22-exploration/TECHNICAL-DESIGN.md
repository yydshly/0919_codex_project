## 2. 两条流程与责任边界

**游客使用：** 看城市与片区 → 点击地标 → 看实拍及游览条件 → 核实费用、预约 → 选具体入口并打开真实地图 → 收藏或安排。未知票价显示“待核实”；未知入口只能“查看景区位置”，不能提供已经确认入口的暗示。

**内容生产：** 收集并核实地点 → 登记坐标系及景观参考 → 计算图幅布局 → 生成候选素材 → 受控合成 → 叠加名称与热点 → 分项验收 → 发布版本。票务更新独立发布；地点迁移或图片重绘需重新检查关联。

职责分为四层：地点库负责身份、地理来源、入口和游览事实；生成管线负责画风、布局、素材与质量报告；游客界面负责展示、选择和状态同步；地图／路线适配与 TREK 分别负责真实位置查询和行程保存。AI 不决定未知事实，地图也不验证建筑是否画对。首轮优先用本地文件验证合同，暂不决定云服务或模型供应商。

## 3. 最小数据合同

所有资料保留来源、采集时间、核实时间、核实状态；缺失字段为 `null`，不能用 `0` 表示未知价格。下面是拟议结构，不是已迁移数据库。

| 记录 | 最小字段与约束 |
| --- | --- |
| Place 地点 | `placeId, name, kind, branchOrCampus, areaId, coordinate, source, verifiedAt, status`；坐标含 `crs, lon, lat, role`，role 区分范围中心、建筑、门店位置 |
| Entrance 入口 | `entranceId, placeId, name, coordinate, accessModes, source, verifiedAt, status`；一个地点可有多个入口，不继承中心点为入口 |
| Reference 参考素材 | `referenceId, placeId, uri, kind, author, license, allowedUse, hash, verifiedAt`；实拍、菜品参考、生成图分别标识，授权未知时为 `null` |
| MapVersion 导览版本 | `mapVersionId, placeDataVersion, layoutVersion, frames, assetManifest, imageHash, auditReport, state`；只有配套验收通过才可发布 |
| Ticket 票务资料 | `ticketId, placeId, ticketType, audience, amount, currency, inclusions, conditions, effectiveFrom, expiresAt, officialUrl, source, verifiedAt, status`；单票、联票和展览分开，过期降级 |
| Hotspot 热点 | `hotspotId, mapVersionId, frameId, placeId, geometry, anchor, layoutRecordId`；geometry 使用画幅归一化坐标，绑定图片版本，不承载导航坐标 |

例如兵马俑保留原型中的范围中心作为导览依据；以下入口与票价仍未知：

```json
{
  "placeId": "terracotta",
  "coordinate": {
    "crs": "EPSG:4326", "lon": 109.277673, "lat": 34.3873627,
    "role": "site-center", "source": "https://www.openstreetmap.org/way/71235670"
  },
  "preferredEntranceId": null,
  "entranceVerification": "pending",
  "ticketDraft": {
    "ticketType": null, "amount": null, "currency": "CNY",
    "officialUrl": null, "verifiedAt": null, "status": "pending"
  }
}
```

上述坐标来自[现有地点库](../../site/xian/places.json)，本轮未重新核实。`placeId` 是图、地图、详情与行程的公共关联键；浏览器焦点只存地点编号，避免两套页面各自维护选中对象。

## 4. 真实坐标怎样进入图片

先保留来源原坐标及坐标系，再生成布局所用的统一坐标；转换过程保存输入、算法版本、误差说明。旧实验使用 GCJ-02，当前原型主要使用 WGS84，两者不得直接拼接。

每个图幅先固定范围、投影、朝向及比例，再把投影平面点变成画幅锚点：`x = padding + scale × (X − Xmin)`，`y = padding + scale × (Ymax − Y)`。这是设计公式，具体投影待实验选择。素材接地点对齐锚点，记录缩放、旋转和允许偏移。标签可避让并画引线，地理锚点保留；需要明显压缩时新增布局规则和验收，不静默移动。

城区太密可使用明确标注的独立放大图，远郊保留主图范围与对应框。跨图幅不比较像素距离；实际距离始终来自真实坐标和道路服务。[当前 atlas.mjs](../../site/xian/atlas.mjs) 的百分比矩形只匹配旧图标签，不能转称为坐标投影结果，也不能直接用于新图。

| 候选生成路线 | 优点 | 主要风险与探索结论 |
| --- | --- | --- |
| 提示词直接生成整图 | 视觉较连贯，制作快 | 地点可能移动、遗漏；难建立像素归属，暂不作地理可信基线 |
| 地理骨架约束整图生成 | 可同时利用布局和画风 | 模型是否遵守约束需实测，后处理必须重新验收 |
| 分地标素材＋程序合成 | 位置、身份与变换可追溯，可局部更新 | 密集点与拼贴感需解决；建议首轮试用，属于设计假设 |

旧[素材实验](F:/codex_project/0913_codex_project/projects/009-city-landmark-map/scenic-material-integration.md)与[合成器](F:/codex_project/0913_codex_project/projects/009-city-landmark-map/app/controlled-compositor.mjs)已有 8 处素材及像素归属检查。它们证明部分错位、遗漏、遮挡和编号串用可被检测；不证明坐标来源真实、素材外形正确或成图审美合格。整图再生成后，原有报告失效。

## 5. 三个小实验及通过标准

下列数量与阈值是本轮拟定的实验门槛。2026-09-22 已完成 E1 四点布局小样，E2 已有实际素材与受控放置结果，完整视觉验收仍待完成；E3 尚未执行。结果见文末。

| 实验 | 操作与产出 | 成功／失败标准 |
| --- | --- | --- |
| E1 地理布局 | 用钟楼、鼓楼、大雁塔、兵马俑构成城区相邻地标与远郊小样；比较连续图、城区放大图，输出坐标转换与锚点清单 | 同图幅全部约定方向正确；坐标系缺失、颠倒经纬度必须拒绝；每点可追溯原始数据。任一静默混用或方向反转为失败 |
| E2 受控素材 | 在 E1 布局放置候选地标，保存参考、提示词、原图、变换、输出哈希；注入交换、漏画、编号串用与遮挡 | 故障全部被拦截；实际主体可见比例暂以 90% 为试验门槛。位置、外形、审美分别报告；外形未核验不得因位置通过而发布 |
| E3 从图到行动 | 3 个地点双向切换图与地图；加入一个中心点无入口案例和一条过期票务资料 | 每次切换编号一致；未知入口不冒充检票口；过期票价不作当前承诺；更新票务后底图哈希不变。错地点、假实时或旧热点套新图均失败 |

## 6. 推进顺序与评审输出

**P0：** 定义记录与状态、登记 4 点来源、保留未知字段，完成 E1；先评审真实坐标如何约束画面。

**P1：** 执行 E2，对比同一布局的生成候选，分别查看外形和美术质量；报告保留失败样本与人工处理耗时。

**P2：** 以通过的版本执行 E3，核实至少一个可用入口及相应官方信息后再演示完整到达链路；实时余票与交易暂不在范围内。

每次评审同时打开对应归档页，记录“保留什么、改变什么、证据是什么”。本阶段交付是设计稿、数据样本、实验图和检查报告；新应用重构、多城发布与生产服务选型在实验结果之后决定。

## 7. E1 实际结果（2026-09-22）

[打开可操作实验](e1/index.html) · [实验说明](e1/README.md) · [检查报告](e1/results.json)

输入沿用 V1 的四点 WGS84 坐标，未重新核实外部事实。实验采用局部球面等距圆柱近似，明确图幅范围、等比缩放与真实锚点；没有生成新插画。对 1200 × 720 画布与 84 px 方形素材占位，连续全域图中钟鼓楼间距为 8.8593 px、重叠 1 对，分区放大后为 103.9667 px、重叠 0 对。

正常两方案均通过输入与输出计算一致性检查；18 个非法输入被拒绝，4 个输出变形故障被检出。页面可以切换两方案、选择地点、调节占位尺寸、注入错误，并导出含当前故障状态的布局记录。

本次支持将“全域定位＋局部放大”作为 E2 候选结构，不证明坐标外部精度、建筑外形、审美、真实入口或路线可达性。固定阈值仅是计算校验容差，不是测量精度；更多地点与实际素材仍需进一步验证。完整误差与来源边界见 [REVIEW](e1/REVIEW.md)。

## 8. E2 实际结果（2026-09-22）

[打开素材与合成对照](e2/index.html) · [实验说明](e2/README.md) · [全部生成记录](e2/data/generation-log.json) · [视觉审查](e2/VISUAL-REVIEW.md)

四张历史实拍作为外观依据，内置 image_gen 的 5 次调用得到 4 张当前候选与 1 张拒收候选。大雁塔首版只有六层且添加高台，二次生成后为七层、删除高台，证明程序身份检查不能替代外形检查。钟楼与鼓楼保留不同的屋顶轮廓；兵马俑仅作为坑内军阵主题符号，不冒充真实园区平面。

程序将四个 PNG 等比放入方框，以图片框中心对齐 E1 地理锚点，网页真实显示这些生成素材。28 项条件检查通过，四类位置／身份／缺失／放大故障检出；4 份原图的哈希、尺寸与透明性均独立匹配。当前 84 px 框无相交，锚点偏移为 0 px。

E2 完整门槛仍未通过：透明边缘有局部彩色残留，建筑细部含生成补绘，背景衔接与整体自然程度未验收；90% 真实主体可见率未测量。中心对齐目前是可复现的放置基准，并非建筑接地点已知。所有正常与故障结果均保持 `releaseReady=false`，完整证据见 [检查结果](e2/results.json)。
