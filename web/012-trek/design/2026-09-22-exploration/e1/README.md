## 实验结论

在同一张 1200 × 720 画布、每处 84 × 84 px 的方形素材占位下：

| 表达方式 | 主图内最小锚点间距 | 素材占位重叠 | 与输入坐标的计算一致性 |
| --- | ---: | ---: | --- |
| A：连续全域图 | 8.8593 px | 1 对（钟楼／鼓楼） | 通过 |
| B：钟鼓楼局部＋城南局部＋临潼局部，附全域定位 | 103.9667 px | 0 对 | 通过 |

四点的真实距离跨度很大：按 V1 冻结坐标计算，钟楼到鼓楼的球面距离约 332 m，到大雁塔约 4.84 km，到兵马俑约 33.85 km。连续图可表达全域关系，但钟鼓楼挤在一起；明确分区并保留定位图，可让地标获得更大的可用空间。

**建议将“全域定位＋局部放大”作为 E2 的候选骨架。** 这不是最终游客页面或全城方案；四点样本不足以证明更多景点、餐厅和手机端的密度仍然合适。局部图位置属于排版，不构成片区的实际方向关系。

## 页面操作

1. 切换 A/B 布局，观察钟鼓楼的锚点与素材占位。
2. 点图上标签或右侧地点，查看保留下来的地理坐标、中心点含义和 OSM 记录链接。
3. 调整 48–160 px 占位尺寸，实时比较两个布局的重叠情况。标签引线仅供阅读，标签位置不是地理锚点。
4. 选择经纬颠倒、坐标系缺失、混入 GCJ-02、输出鼓楼位置被移动等故障；输入无效时不绘图，输出错误时明确显示未通过。
5. 下载当前布局与检查记录。故障样本也保留故障类型和失败结果，不伪装成正常输出。

## 数据及方法

- 输入 [`data/input.json`](data/input.json) 由 [`../data/baseline-places.json`](../data/baseline-places.json) 提取，保留固定编号、来源和坐标语义。实际相对路径从本目录为 `../data/baseline-places.json`；输入文件内 provenance 路径以其自身所在目录为基准。
- 原始数据 SHA256：`7b363a3a44d8dc94c75851683d82ae313216d889a9eaf71dd422052da4d94dd3`。
- 四点明确为 WGS84 / EPSG:4326。钟楼、鼓楼、大雁塔为建筑中心，兵马俑为景区范围中心；均不视为已核实入口。本实验没有重新核实外部事实。
- 局部平面采用球面等距圆柱近似，标准纬线／纬度原点 34.26°、中央经线 108.94°、R = 6371008.8 m；方法参考 [PROJ 官方文档](https://proj.org/en/stable/operations/projections/eqc.html)。这是布局诊断用途，不作为导航测绘。
- 图幅内等比缩放、居中；全域定位小图单独标记，不参与主图素材碰撞统计。同图幅主图每点唯一；定位图的重复表达有明确角色。
- 碰撞指轴对齐正方形相交，不含标签，也不等于真实图片透明区域的遮挡。后续 E2 需用实际素材再验收。
- 数据来自 OpenStreetMap，© OpenStreetMap contributors，[ODbL](https://www.openstreetmap.org/copyright)。

## 独立检查

已用独立 Python 计算的数值基准对照投影和球面距离。两种正常布局通过；18 个非法输入全部拒绝，4 个输出布局故障均检出。具体案例及数值见 [`results.json`](results.json) 与 [`REVIEW.md`](REVIEW.md)。0 px 的锚点偏移表示计算结果相符，不表示真实地点达到像素级定位精度。
